# RecordReader v1 Design

## Goal

Build a lightweight Chinese SwiftUI iPhone recording player that lets the user choose a recordings folder, browse audio files, play a selected recording, favorite recordings, classify recordings, and generate Chinese subtitle text from the selected recording.

## Product Boundary

RecordReader v1 is a lightweight iPhone-only iOS app. It does not depend on SmartSub, Whisper, translation providers, desktop components, or bundled speech models. It uses the native iOS Speech framework with the `zh_CN` locale only.

Included in v1:

- Folder picker for recordings.
- Chinese-only UI copy.
- Chinese-only speech recognition locale: `zh_CN`.
- Audio scanning for common formats: `aac`, `aif`, `aiff`, `caf`, `flac`, `m4a`, `mp3`, `wav`.
- Dark SwiftUI player screen inspired by the provided reference image, without cover art.
- Playback controls for the selected recording.
- Favorite toggle.
- Category assignment and category/favorite filters.
- Subtitle status model: `notStarted`, `recognizing`, `ready`, `failed`.
- iOS `Speech` framework recognition entry point for generating Chinese subtitle segments.
- Local JSON metadata for favorites, categories, subtitles, and the last selected folder bookmark.
- GitHub Actions cloud build path because the local machine does not have Xcode installed.

Deferred after v1:

- Whisper.cpp or Core ML model packaging.
- Model download and model selection.
- Translation and bilingual subtitles.
- Batch processing.
- SRT/VTT export.
- iCloud sync.
- Desktop, iPad-specific, or cross-platform layouts.
- Custom metadata search.

## Architecture

The repository has two layers:

- `RecordReaderCore`: Swift Package library with file scanning, recording metadata, subtitle value types, and JSON metadata persistence.
- `RecordReader`: SwiftUI iPhone app generated by XcodeGen. It owns the Chinese UI, file picker, AVFoundation playback, and Chinese Speech framework integration.

This keeps business rules and metadata persistence testable without a simulator. The app layer remains thin and platform-specific.

## UI

The first screen is a player, not a library dashboard. The visual direction is dark, quiet, and audio-focused:

- Top left: folder picker.
- Top center: current filter title.
- Top right: recordings list.
- Middle: subtitle panel replacing album art.
- Below: recording title, category, favorite button, action menu.
- Bottom: progress, rewind/play/forward, and quick filter/category actions.

The app does not use cover images in v1.

## Data Flow

1. The user chooses a folder with the iOS document picker.
2. The app stores a bookmark for reopening that folder later.
3. `RecordingLibraryScanner` reads supported audio files and joins each file with local metadata by stable path key.
4. UI mutations update `RecordingLibraryMetadata`.
5. `RecordingMetadataStore` writes metadata to app support as JSON.
6. Playback loads the selected file with `AVAudioPlayer`.
7. Subtitle recognition uses `SFSpeechURLRecognitionRequest` with `SFSpeechRecognizer(locale: Locale(identifier: "zh_CN"))` and stores recognized segments back into metadata.

## Error Handling

RecordReader fails fast when a required state is missing:

- Missing folder: show a readable folder-not-found error.
- Unreadable folder: show a readable folder-unreadable error.
- Refresh without folder: ask the user to choose a folder.
- Favorite/category/subtitle action without selection: ask the user to choose a recording.
- Invalid metadata JSON: fail load with a clear invalid-metadata message instead of silently dropping data.
- Speech permission denied or unavailable recognizer: mark subtitle as `failed` with an actionable message.
