# 真机可用性验证

RecordReader 的 CI 会验证 Swift 测试、Xcode 工程生成、模拟器构建和 unsigned IPA 产出；真机验证需要在 iPhone 上执行，因为文件选择、安全作用域、播放、语音识别权限和 iOS Speech 服务都依赖设备环境。字幕识别读取所选音频文件本身，不采集麦克风，也不监听扬声器或耳机输出。

## 准备

1. 从 GitHub Actions 下载最新 `RecordReader-unsigned-ipa`，或用开发者证书重新签名安装。
2. 在 iPhone 上准备三类文件：
   - iOS 语音备忘录导出的 `.m4a`。
   - 一个普通 `.mp3`。
   - 一段包含清晰中文人声的短录音，建议 30 秒以内。
3. 确认系统设置允许使用语音识别。首次点击“识别中文字幕”时，系统会弹出授权请求。

## 验证用例

### 1. 直接导入音频文件

1. 打开 App。
2. 点击左上角波形加号图标，或空状态的“选择音频”。
3. 直接选择 `.mp3` 和 `.m4a` 文件后点击“打开”。
4. 预期：播放器立即显示选中的录音，文件扩展名显示为 `MP3` 或 `M4A`。

### 2. 导入录音文件夹

1. 点击左上角文件夹图标，或空状态的“选择文件夹”。
2. 选择包含多段录音的文件夹。
3. 预期：播放器立即显示第一条支持的录音；非音频文件不会出现。
4. 如果文件夹里没有支持的音频，预期：空状态显示明确错误提示。

### 3. 播放和拖动进度

1. 选择一段录音。
2. 点击播放。
3. 确认手机物理音量不是 0，并测试静音拨片开启时仍可播放。
4. 拖动进度条到中间位置后松手。
5. 预期：播放时间跳到对应位置，播放可以继续。

### 4. 上一首、下一首和连续播放

1. 导入至少三段录音。
2. 选择中间一段录音。
3. 点击上一首和下一首按钮。
4. 预期：播放器切换到相邻录音。
5. 播放一段不是列表末尾的录音直到结束。
6. 预期：App 自动切换并播放下一段录音。

### 5. 搜索、排序和批量管理

1. 打开录音列表。
2. 搜索录音标题、分类名和格式名，例如 `mp3`。
3. 预期：列表只显示匹配录音。
4. 切换排序方式：名称、最新修改、最早修改、文件大小、格式。
5. 预期：列表按对应方式重排。
6. 点击“选择”，多选录音。
7. 批量收藏、取消收藏、设置分类、清除分类。
8. 预期：列表状态和播放器当前录音状态同步更新。

### 6. App 自动识别中文字幕

1. 选择一段包含清晰中文人声的短录音。
2. 点击更多菜单中的“识别中文字幕”。
3. 允许语音识别权限。
4. 可戴上耳机，或不播放音频，直接等待识别完成。
5. 预期：字幕状态从“正在识别”变为“字幕已生成”，字幕面板显示识别出的中文文本。
6. 预期：识别结果来自音频文件内容本身，不依赖手机外放声音、耳机声音或麦克风采集。

### 7. 识别失败提示

分别验证以下情况：

- 拒绝语音识别权限。
- 选择没有人声的音频。
- 选择被移动或不可读取的文件。
- 在网络或系统语音识别不可用时点击识别。

预期：字幕面板显示“识别失败”，并给出能指导下一步操作的中文错误信息。

## 通过标准

- MP3 和 iOS 录音文件都能直接导入。
- 文件夹导入仍可用。
- 播放、暂停、前后 15 秒、拖动进度都可用。
- 上一首、下一首和连续播放可用。
- 搜索、排序和批量管理可用。
- App 能自己调用 iOS Speech 生成中文字幕，不需要用户提供字幕文件。
- 字幕识别读取音频文件本身；戴耳机、静音或不播放音频都不应该改变识别来源。
- 失败时能显示具体原因，而不是只显示通用失败。
